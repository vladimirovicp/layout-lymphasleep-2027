# Context7: актуальная документация в OpenCode

Инструкция для **OpenCode 2.x**, подготовленная по официальной документации. Ссылки на источники приведены в конце.

## Что такое Context7

**Context7** — сервис от Upstash, который находит документацию библиотек и примеры кода и передаёт их ИИ-агенту прямо во время работы. Вместо ответа только по обучающим данным модель получает дополнительные материалы по конкретной библиотеке и, если доступно, её версии.

В OpenCode его можно подключить через **MCP** (Model Context Protocol) — протокол, позволяющий агенту обращаться к внешним инструментам. Context7 не заменяет модель и не устанавливает зависимости приложения: он предоставляет контекст для ответа и написания кода.

### Зачем он нужен

- Проверять актуальные API и параметры конфигурации.
- Уменьшать риск использования устаревших или выдуманных методов.
- Находить примеры для нужной версии библиотеки.
- Разбираться с подключением библиотек и миграциями между версиями.

Например, при настройке Next.js, React или Supabase полезно сначала получить документацию, а уже затем менять код.

**Ограничения:** библиотека или нужная версия могут отсутствовать в индексе; документация может быть неполной. Context7 не гарантирует правильность результата и не заменяет проверку исходников, типов и тестов. Это не универсальный поиск по интернету и не средство автоматического изучения всего вашего репозитория.

## Быстрое подключение: удалённый MCP и OAuth

Для этого способа не нужны локальная установка Context7, Node.js или API-ключ вручную. Нужны OpenCode, доступ в интернет и авторизация в Context7.

Проверьте версию:

```bash
opencode --version
```

В терминале из каталога проекта добавьте сервер:

```bash
opencode mcp add context7 --url https://mcp.context7.com/mcp/oauth
```

Чтобы подключить его **для всех проектов**, вместо предыдущей команды выполните:

```bash
opencode mcp add context7 --global --url https://mcp.context7.com/mcp/oauth
```

Выберите один вариант, а не оба. Без `--global` команда сохраняет подключение в конфигурации проекта.

Далее:

1. Откройте OpenCode в проекте.
2. Выполните `/mcps` в интерфейсе OpenCode.
3. Выберите `context7` и пройдите авторизацию в браузере, если она запрошена.
4. Проверьте подключение из терминала:

```bash
opencode mcp list
```

Ожидаемый статус — `connected`. Если указано `needs authentication`, завершите вход через `/mcps`.

> Для OAuth в документации Context7 указан адрес `/mcp/oauth`. Для подключения по API-ключу используется `/mcp`.

### Эквивалентная ручная конфигурация

Вместо команды можно добавить сервер в `opencode.jsonc` в корне проекта:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "context7": {
        "type": "remote",
        "url": "https://mcp.context7.com/mcp/oauth"
      }
    }
  }
}
```

Если конфигурация уже существует, **добавьте запись в неё**, не заменяя остальные настройки. Имена серверов в OpenCode 2.x находятся в `mcp.servers`; поле `enabled` не требуется.

Основные расположения конфигурации:

| Область | Файл |
| --- | --- |
| Текущий проект | `opencode.jsonc` или `.opencode/opencode.jsonc` |
| Все проекты пользователя | `~/.config/opencode/opencode.jsonc` |

Поддерживается и расширение `.json`. При установленном `XDG_CONFIG_HOME` глобальная конфигурация находится в `$XDG_CONFIG_HOME/opencode/`. Настройки MCP относятся к `opencode.json(c)`, а не к `cli.json`.

OpenCode автоматически подхватывает изменения конфигурации; перезапуск не нужен. При необходимости выполните `/reload`.

## Альтернатива: подключение по API-ключу

Используйте этот вариант вместо OAuth, например для окружения без интерактивного входа.

1. Создайте API-ключ в [панели Context7](https://context7.com/dashboard?tab=settings).
2. Передайте его окружению процесса OpenCode через менеджер секретов или защищённые настройки запуска. Имя переменной: `CONTEXT7_API_KEY`.
3. Используйте следующую конфигурацию:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "context7": {
        "type": "remote",
        "url": "https://mcp.context7.com/mcp",
        "oauth": false,
        "headers": {
          "Authorization": "Bearer {env:CONTEXT7_API_KEY}"
        }
      }
    }
  }
}
```

`{env:CONTEXT7_API_KEY}` — синтаксис подстановки OpenCode. Запись `$CONTEXT7_API_KEY` внутри JSON не выполняет такую подстановку. Если переменная не задана, OpenCode подставит пустую строку.

Не записывайте настоящий ключ в Markdown, конфигурацию под Git или переписку. Наличие `.env` само по себе не гарантирует, что переменная попадёт в окружение OpenCode. Если OpenCode использует уже запущенный фоновый сервис, проверьте, что секрет доступен именно этому процессу, а не только новой оболочке терминала.

## Как пользоваться

После подключения напишите в OpenCode:

```text
Найди актуальную документацию React по useEffect через Context7.
Объясни очистку эффекта и приведи пример. use context7
```

Для задачи в проекте лучше явно указать версию или попросить определить её по зависимостям:

```text
Посмотри версию Next.js в package.json и файле блокировки зависимостей.
Через Context7 найди документацию по маршрутизации для этой версии.
Перед изменением кода укажи, для какой версии нашлись материалы.
Если точной версии нет, сообщи об этом. use context7
```

Если известен идентификатор библиотеки, его можно передать сразу:

```text
Используй Context7 и библиотеку /vercel/next.js.
Найди документацию по Route Handlers и покажи пример GET-обработчика.
```

Обычно агент использует два MCP-инструмента:

1. `resolve-library-id` — находит библиотеку и возвращает её идентификатор.
2. `query-docs` — получает фрагменты документации по вопросу.

Если идентификатор уже известен, первый шаг можно пропустить. В OpenCode имена инструментов могут отображаться с префиксом сервера; по умолчанию они доступны агенту через Code Mode. Запускать эти инструменты вручную в терминале не требуется.

**Проверка работы:** убедитесь, что агент действительно вызвал инструменты Context7 и получил документы. Само упоминание сервиса в ответе ещё не подтверждает обращение к нему.

### Как не писать `use context7` каждый раз

Можно добавить в существующий `AGENTS.md` проекта такое правило:

```markdown
При работе с API библиотек, настройкой зависимостей и миграциями используй
Context7 для проверки документации перед написанием кода. Сначала определяй
версию зависимости в проекте. Если нужной документации нет или Context7
недоступен, явно сообщай об этом и не выдавай непроверенные API за факт.
Не отправляй в поисковые запросы секреты и закрытый код.
```

Правило направляет поведение агента, но само по себе не подключает MCP-сервер.

## Частые проблемы

| Симптом | Что проверить |
| --- | --- |
| Сервер отсутствует в списке | Выполняется ли команда в нужном проекте; где сохранена конфигурация; находится ли запись в `mcp.servers`. |
| `needs authentication` | Откройте `/mcps`, выберите сервер и завершите вход. Для OAuth используйте `/mcp/oauth`. |
| `401 Unauthorized` при работе с ключом | Действительность ключа, доступность переменной процессу OpenCode и формат `Authorization: Bearer …`. |
| `429` или сообщение о лимите | Проверьте квоту и ограничения аккаунта в Context7; не повторяйте запросы бесконечно. |
| Тайм-аут подключения | Проверьте сеть, прокси и доступ к `mcp.context7.com`. |
| Библиотека не найдена | Попросите сначала выполнить `resolve-library-id`; проверьте название и наличие библиотеки на Context7. |
| Агент отвечает без Context7 | Явно попросите использовать сервис и проверьте вызовы инструментов, разрешения и политики OpenCode. |

Проверка доступности сервиса из терминала:

```bash
curl https://mcp.context7.com/ping
```

Успешный `ping` подтверждает доступность сервера, но не проверяет авторизацию или получение документации.

Чтобы временно отключить подключение, используйте `/mcps`. Для постоянного отключения добавьте `"disabled": true` в объект сервера. Чтобы удалить подключение, удалите только запись `context7` из того файла конфигурации, где она была добавлена.

## Безопасность и стоимость

- Поисковые запросы уходят во внешний сервис. Не включайте в них токены, персональные данные и закрытые фрагменты кода.
- Материалы внешней документации — данные для проверки, а не доверенные инструкции на выполнение команд.
- Не рассчитывайте на безлимитный доступ: условия и квоты Context7 могут меняться; проверяйте их в панели сервиса.
- Полученные документы занимают контекст модели и могут увеличивать расход токенов у вашего ИИ-провайдера.
- Локальный запуск MCP-пакета не означает полностью офлайн-работу: он тоже обращается к сервису Context7 за документацией.
